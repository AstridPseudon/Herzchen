# Creative work protocol

Use shared work records to track a bounded scene outcome. Establish its brief and dialogue/timing, prepare the visual edit, and obtain the intended human/agent feedback against an identified result. Revise tasks and documents together through the project sheet. Keep creative intent, versioned assets and actual render jobs linked but distinct.

Editorial metadata such as mood, continuity group and desired take count is descriptive context. It cannot change primary media, authorise provider spend or mark a task accepted. Use the owning creative operation for managed state. A successful render job may still need creative revision.

This protocol has no mandatory Otto hierarchy, Megado XHARD classification or model-review schedule. Select appropriate profiles and explicit iteration/spending limits for the actual project. Preserve source/asset/decision identity through revisions; attach dialogue and notes using shared document links rather than copied task-specific files. Follow the same single-editor, autosave, idle check-in and cleanup contract. Never delete media or a running capability's pinned files when an authoring checkout expires.
