# Execution mechanics: source, proof and safe publication

Review timing, profile and counts come from the active run and pragmatic-review.md, not this reference. Planning-only inspection remains read-only. A chosen source snapshot must include or explicitly exclude authoritative dirt with preservation, not silently assume HEAD captures it.

## Before source mutation

Record invoking repository/root, actual ref/commit/tree, staged/unstaged/untracked state, worktrees, remotes, relevant dependency/runtime identity, actual authority and protected local work. Keep one declared control root and a separately identified execution worktree. Do not reset, stash, clean or broad-stage unrelated dirt. Repository-local ignoring of `.otto` does not mean its live database or transcripts should be force-added. Output receipts exclude credentials.

Use one isolated write owner per overlapping surface, disjoint workers where contracts are ready, and explicit source handoffs. An owner may hold several related responsibilities; one worker never receives conflicting orders from two managers. A commit hash does not prove tests ran, and a Git worktree is not a security sandbox.

Before expensive work check real storage/resource headroom and expected fan-out. Do not use a small read-only query as an excuse for a broad audit. Stop equivalent retries after disk or environment failure until the cause and partial output are checked. Never reclaim another project's files, active source, user media or required evidence as a shortcut.

## Incremental commits and publication

Commit coherent named source/test increments after relevant focused checks where practical and before handoffs or substantial pauses. A preservation commit may contain unfinished work, but label WIP, failed/not-run checks and open obligations honestly. Code-ready handoff includes passing relevant checks and consumed source/contract identities. Do not wait for model review to commit; a checkpoint is not acceptance.

Bind input upstream separately from approved publication fork/new owned repository, actual push URL and explicit allowed branch/ref. Ownership of a GitHub account or a remote named origin is not permission. Resolve actual push URLs and rewriting, workflow/protection side effects and intended content before each push. No bare push, wildcard/all/mirror/tag push, force/protection bypass or implicit upstream PR. In the current portfolio upstreams are read-only. Elsewhere the actual adopted mandate governs; this skill never supplies a new target grant.

Inspect only the named staging paths and staged diff; protect secrets, unowned source, large artifacts and live control data. Local commits remain useful during network/permission failure; report that no remote checkpoint exists. Reconcile a possibly successful push by exact remote/ref/head before retry. Do not select a different remote because the approved one is unavailable.

## Evidence ladder

Run focused fixtures during implementation; affected integration when contracts converge; the broad affected campaign on a settled candidate; and costly/live/full-scale operations only when a criterion needs them and the actual environment/budget allows it. Prefer tests or real tool use over reviews for observable questions. Reuse existing passing evidence only when candidate, inputs and relevant environment still match. After a correction rerun its affected closure, not unrelated suites.

A useful receipt names exact source, command/tool, inputs/environment, actual output/result, duration and evidence reference. Distinguish retained baseline failures, new regressions and missing proof. Never delete a safety assertion to make extraction green. For a real transition, preserve valuable data, use a representative fixture, and perform one necessary source/data inventory and proportionate rehearsal. Do not build a migration framework merely because there might someday be users.

## Frozen review

When an adopted review is actually due, freeze the exact reviewed candidate and relevant evidence; stop its mutators. Normally commit in the approved execution worktree; where commit authority is absent, create an explicit non-destructive snapshot with a content manifest. The read-only reviewer has independent context and output/scratch outside frozen source. Verify unchanged candidate/evidence identities before accepting applicability. An old PASS cannot certify changed inputs without a recorded valid basis.

The packet includes complete concise North Star, current mandate, precise criteria and selected risk/question, source/diff, actual checks, current concrete finding/oracle dispositions and relevant dependency closure. Do not seed the reviewer with persuasive prior PASS narratives. Findings are not criteria expansions. Technical reviewers are leaves; no recursive panels.

## Finish

Map every promised outcome to observed evidence; distinguish complete, blocked, failed, undetermined, retryable and needs-authority. Acceptance and remote publication are different acts. The final broad campaign and selected holistic judgment precede promotion. Integration chooses actual producer/consumer order and expected heads; several repositories are not atomic. If two succeed and one fails, preserve the partial state and reconcile. Do not automatically force or revert history.

Verify final allowed targets and tree/dependency equivalence (including squash/rebase effects), run the small supported-entrypoint smoke and return a source manifest. A source merge is not package publication, production deployment or old-data migration. Hand off the actual remaining limits, pending work, recovery route and canonical state location.

Discovery-index scripts may be used in the file-based environment if present and verified; failure of a convenience index is not an acceptance gate. Native Otto/Herzchen uses its actual project discovery API. Never depend on an unavailable helper to create fictional execution evidence.
